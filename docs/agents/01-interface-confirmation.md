# 接口确认

本阶段把用户提供的参考资料、参考实现和需求收敛为可评审的接口契约。新接口只有在用户确认数学语义、输入输出和支持边界后，才能进入 CPU 标杆生成。

## 输入门禁

用户至少提供一种可定位版本的参考资料或参考实现：

- 参考实现代码或固定 commit 的链接。
- 已发布接口文档、schema 或 API 定义。
- 能表达输入、输出和属性语义的测试或可运行示例。
- 论文或公式可以作为补充，但不能单独替代工程参考实现、接口文档或测试。

同时确认参考资料或参考实现的来源、版本、许可证约束、预期支持范围和目标调用入口。缺少材料、版本不明确或无法判断哪份材料权威时，先列出缺失项并请求用户补充，不进入实现。

## 分析用户提供的材料

按以下顺序建立证据链：

1. 公开接口、文档和用户明确说明决定对外契约。
2. 用户提供的测试和示例补充边界、默认值及异常行为。
3. 用户提供的参考实现用于还原公式、计算顺序、状态传播和数值细节。
4. 论文或相邻实现只用于解释和交叉验证，不覆盖用户确认的契约。

不同材料不一致时，记录“材料、差异、候选解释、影响”，由用户确认采用哪一种语义。不得自行选择最容易实现的版本。

## 既有算子特性修改分流

修改既有算子特性时，先读取当前接口契约、CPU 标杆、设计、实现和测试，形成“本次改变、本次保持不变、兼容性影响”的差异清单，再按下表选择后续阶段：

| 发现的变化 | 后续流程 |
| --- | --- |
| 公开参数、返回值、默认值、ABI、数学语义、dtype/layout 行为、支持范围或异常行为变化 | 更新接口契约并取得用户确认，然后进入 `02` |
| 接口契约不变，但 CPU 标杆或预期结果需要修正、补充 | 记录接口无变化，进入 `02` 更新并重新验收 CPU 标杆 |
| 接口契约和 CPU 标杆均不变，只修复未达到既有约定的实现 | 冻结 `01`、`02`，直接进入 `03` 设计修复方案 |
| 对外行为不变且目标仅为性能提升 | 转入根 `AGENTS.md` 的算子优化流程 |

不得把支持范围扩大、语义变化或接口变化描述为普通实现修复。未受影响的接口和行为在后续阶段保持不变。

## 接口契约

接口确认记录至少包含：

| 项目 | 需要确认的内容 |
| --- | --- |
| 接口身份 | 算子名、公开入口、L2/L0/aclnn/Python 层级和版本 |
| 输入 | 名称、顺序、required/optional、shape、dtype、format、layout、device 和语义 |
| 属性 | 名称、类型、默认值、取值范围、是否可由 descriptor 或已有信息推导 |
| 输出 | 数量、顺序、shape、dtype、layout、状态输出和别名关系 |
| 数学语义 | 公式、计算顺序、归一化、缩放、mask、状态更新和返回值语义 |
| 边界行为 | 空输入、partial chunk、padding、无效区、极端值和不支持组合 |
| 错误行为 | host 校验、错误类型、返回码和报错条件 |
| 支持范围 | SoC、fixed/varlen、head 关系、K/V/chunk 维度，以及本次明确不支持的功能 |
| 性能目标 | 目标 shape、基线、目标指标和允许的 correctness fallback |

对预留但暂不支持的参数，明确其公开形态、host 拦截和未来兼容策略。不能验证的能力不得宣称支持。

## 接口与 ABI 约束

- 优先复用已有接口信息，不把可由 tensor descriptor、InferShape、host tiling、tiling data 或 workspace 推导的信息新增为参数。
- op_host、InferShape、tiling、kernel、op_api、schema、Python wrapper、公开文档和测试中的名称、顺序、类型及默认值必须一致。
- 已发布接口或 ABI 的变更按根 `AGENTS.md` 的强制红线执行；需要评审的变更在取得确认前不得进入开发。
- 同一算子在所有支持 SoC 上保持同一公开接口和 L0 原型，平台差异留在实现内部。

## 阶段输出

提交给用户确认的内容应简洁、可逐项判断：

1. 参考资料或参考实现的来源和固定版本。
2. 接口签名与逐参数说明。
3. 数学语义和状态语义。
4. 支持矩阵、性能目标，以及本次明确不实现的内容。
5. 边界、异常及兼容性规则。
6. 尚未解决的问题和需要用户选择的差异。
7. 对既有算子的特性修改，还需列出改变项、保持不变项及后续阶段分流结论。

新增接口或改变既有接口契约时，只有接口和语义获得用户确认，且没有阻塞性歧义，才进入 [`02-reference-generation.md`](02-reference-generation.md)。仅修复既有实现且接口契约和 CPU 标杆均不变时，按上表直接进入 `03`。
