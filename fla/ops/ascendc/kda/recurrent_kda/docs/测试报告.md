# RecurrentKda 6.0 测试报告

## 1. 测试结论

RecurrentKda 6.0 的 IR、aclnn、tiling、kernel、Python wrapper 和相关测试已完成更新。Ascend 910B 单算子 run 包、Python wheel 及可选 legacy extension wheel 均构建成功，用户指定的三组验收测试全部通过。

## 2. 主要验证范围

- `gate`、`beta` 原生接收 FP32、BF16、FP16；BF16/FP16 在 kernel 内转换为 FP32 参与递推计算。
- `cuSeqlens`、`ssmStateIndicesOptional`、`numAcceptedTokensOptional` 原生接收 INT32、INT64。
- aclnn wrapper 不再对 `gate`、`beta` 和整数元数据执行 `MaybeCast`。
- 支持 BSND 与 TND 输入。
- 支持 raw gate、safe gate、预计算 log gate、beta sigmoid。
- 支持 `initial_state`、`output_final_state`、`inplace_final_state`。
- 支持 V-first 与 K-first 两种 state 布局。
- 支持省略 `cuSeqlens` 的 dense BSND 场景。
- 支持无初始 state 的非原地 final state 场景。

## 6. Ascend950 纯 AIV RegBase 优化复测

### 6.1 最终实现

- 保持 `KERNEL_TYPE_AIV_ONLY`，不启动 AIC，不做 CV 分解；
- arch35 继续使用 MicroAPI RegBase 热点实现；
- 每个 AIV 从自身 `blockIdx` 开始，以 `GetBlockNum()` 为步长直接处理 `B * NV` 任务，取消全量任务扫描和取模判断；
- 输入队列保持单 buffer；输出队列保留 tiling 已有的 1/2 buffer 自适应逻辑。

### 6.3 msprof 性能

固定 case：`B=1, T=8, Hk=Hv=12, K=V=128`，8 条单 token 逻辑序列，5 次预热、10 次正式采样，Block Num 为 56。

| 版本 | 均值 (us) | 中位数 (us) | 最小 (us) | 最大 (us) | 结论 |
|---|---:|---:|---:|---:|---|
| 原纯 Vector 基线 | 20.189 | 20.280 | 19.239 | 20.923 | 基线 |
| MIX 1AIC:2AIV 空 AIC 版本 | 24.170 | - | - | - | 劣化 |
| 纯 AIV + RegBase | 19.319 | 19.173 | 18.937 | 19.985 | 提升 |
| 纯 AIV + RegBase + 直接任务步进（首次） | 17.711 | 17.754 | 16.528 | 18.226 | 最优采样 |
| 最终安装状态复测 | 18.381 | 18.186 | 17.662 | 19.478 | 相对基线提升约 9.0% |

最终 profiler 字段为 `Task Type=AI_VECTOR_CORE`、`Mix Block Num=0`、`aicore_time=0`，说明最终 kernel 不再调度 AIC。最后一条有效流水采样中，AIV time 19.18 us、Vector 6.702 us、Scalar 7.183 us、MTE2 8.991 us、MTE3 1.895 us。

### 6.4 Cube 与 double buffer 结论

原 24 us 报告中的 `aic_mac_time=0`，没有 Cube MAC；AIC scalar/MTE 字段来自 MIX kernel 启动的空 AIC 调度。改回 `KERNEL_TYPE_AIV_ONLY` 后 `aicore_time=0`。

当前输入队列深度为 1，输出队列支持 tiling 自适应深度 2。本 case 每条序列只有 1 token，且 `V=128` 可在单个 `vStep` 完成，没有可供输入 double buffer 重叠的下一迭代；强行增加输入 buffer 会占用 UB 并可能压缩 `vStep`，因此未采用。单 beta 细粒度预取候选实测 21.365 us，已回退。
