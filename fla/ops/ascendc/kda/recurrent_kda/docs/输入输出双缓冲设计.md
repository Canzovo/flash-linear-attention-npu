# RecurrentKda 输入输出双缓冲设计

## 1. 目标与基线

本次仅增加输入、输出双缓冲流水，不改变公开 API、dtype、layout、state
alias/stride、数学计算顺序或 ATK 固定用例。正式基线取自
`tests/ATK/TEST_REPORT.md`，性能只使用 ATK Device profiler。

## 2. 最终范围

基线的 State/Attention 输出队列已支持 tiling 选择 1 或 2 槽；本次保留
该输出双缓冲。新增部分集中在占主要输入流量的 State：

- legacy、arch35 的 `stateInQueue_` 从 1 槽改为 2 槽；
- host UB 模型按两个 State 输入 tile 计费；
- 当前任务计算期间预取下一有效任务的首个 State tile；
- Q/K/V/Gate/Beta 保持单槽，避免 Gate 的 VEC 预处理干扰热点流水；
- 不修改公共接口、tiling data 字段及数值算法。

## 3. State 输入流水

    slot 0: current task, V tile 0
    slot 1: current task, V tile 1
    DeQue current tile 0
    slot 0: prefetch next task, V tile 0
    slot 1: current task, V tile 1
    Compute current tile 0/1
    进入 next task 时，其 V tile 0 已在队列中

当前任务若还有第 n+2 个 V tile，空槽优先补当前任务；当前所有 tile 均已
入队后，才预取下一任务首 tile。legacy 选择当前 core 的下一有效 head；
arch35 选择相同 block stride 的下一有效 task。任务元数据在预取前完成
初始化、seq range 与 state slot 校验。

## 4. 输出与 UB

State/Attention 输出保持原有 1/2 槽 profile，双槽时写回上一 pending 槽，
每个 V tile 结束时 flush。State 输入双槽的 host 公式为：

    fixedUbBytes = 单槽 Q/K/V/Gate/Beta + scalar + guard
    vStepCoeff = 2*stateDtypeBytes*K
               + stateOutBufferNum*stateDtypeBytes*K
               + attnOutBufferNum*2 + 8*K + 8

host 仍优先选择 V tile 次数更少的 profile，再比较输出深度与 vStep。

## 5. 生命周期约束

- State 输入遵循 `AllocTensor -> DataCopy -> EnQue -> DeQue -> Cast/Copy -> FreeTensor`。
- FIFO 中当前任务剩余 tile 位于下一任务首 tile 之前。
- 下一任务元数据全部有效后才能预取。
- 槽只在 `FreeTensor` 后复用，不在 `EnQue` 后修改。
- 不引入跨 core 依赖、全局同步或无配对 EventID。
- 输出保持原有别名与原地 state 写回语义。

## 6. 验证

1. 按 `README.md` 方式 A 构建 ascend950 wheel；
2. `bash run_atk.sh accuracy` 要求 8/8 PASS；
3. `bash run_atk.sh performance` 要求 8/8 SUCCESS；
4. 与 `tests/ATK/TEST_REPORT.md` 的 Device profiler 基线比较。
