# RecurrentKda 输入输出双缓冲性能优化测试报告

## 1. 最终结论

最终交付选用第9轮性能版本，并正向修复其多 token Beta UB 越界问题；输入/输出
双缓冲、按 head 压缩 Beta、K=128 融合归约及后续流水优化均予保留。方式A构建
成功，四项精度门禁全部通过，ATK performance 连续两轮8/8执行成功。

最终两轮8-case Device总耗时分别为990.9629 us和977.7254 us，均值984.3442 us。
相对 `TEST_REPORT.md` 基线1322.0956 us降低337.7514 us，整体提升25.5467%。
均值相对第9轮稳定复跑992.5620 us再提升0.8279%，确认精度修复未引入可见性能
回退。性能数据来自 ATK profiler，不使用 Python wall time。

## 2. 修改范围

- State输入队列采用双缓冲；
- 当前任务计算期间预取下一有效 State tile；
- 保留 State/Attention 输出双缓冲；
- 保留第9轮按 head 压缩 Beta、K=128融合归约、衰减/状态更新融合和MicroAPI优化；
- 将 Beta UB 队列容量修正为每个多 token 槽位一个32-byte block，消除小NV下越界；
- 未修改测试脚本、精度容差或算子接口。

## 7. 问题与风险结论

- 第4轮期间发生服务器重启和恢复期507033；触发原因未知，不归因于 kernel。
- 固定 ATK 仅覆盖单 token decode；本次补齐PTA、torch_custom及多 token完整pytest。
- 原精度问题不是压缩Beta的语义错误，而是Beta UB队列容量与32-byte槽位布局不匹配。
- `aiv_vec_ratio` 用于定位瓶颈，不能单独作为保留门槛；最终以精度、完整回归和
  Device耗时共同判定。
- 四项精度门禁和两轮性能终验均通过，未发现剩余功能回归。
